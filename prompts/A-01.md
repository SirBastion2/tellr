# A-01 · Library and engine interface (A1 half)

**Agent A1 · hours 2–3 · worktree `tc-a1`** · depends on `contract-v1`

**Read only:** architecture §5, §15 · `reference_impl.py` (library section) · `contract/library.schema.json`, `contract/library.json` · docs/ROSTER.md §5.1

## Goal

A library that refuses to boot when it is wrong, and a frozen engine interface A2 can build against.

## You may create or edit

- `engine/__init__.py`
- `engine/library.py`
- `engine/testing.py`
- `library/*.yaml`
- `tests/library/**`

## Steps (tests first)

1. **Tests first, `tests/library/`:** the shipped library boots; an unresolved ID fails boot; a yes/no question without `asserts_on` fails boot; a signal without a rationale fails boot; the export served at `/library` validates against `contract/library.schema.json`.
2. Port the library from `reference_impl.py` into `library/*.yaml` (patterns, look-alikes, purposes, questions, signals with weights, context chips per §5.7), taking copy from `contract/library.json`. Start with the six questions; the bank grows toward ~40 later. Mark the three patterns the architecture doesn't specify `review: compliance` (draft §7.3).
3. **Freeze the engine interface** (docs/ROSTER.md §5.1) and commit `FakeEngine`. Signatures in `engine/__init__.py` are finalised by A1:

```python
def load_library(path) -> Library                                 # §5, boot validation

def candidates(state, lib) -> tuple[Stage, list[QuestionId]]      # §7.2
def stop(state, lib, cands) -> Stop | None                        # §8.4, CHANGE-000 precedence
def rule_choice(cands) -> QuestionId                              # §7.3
def check_command(events, command, lib) -> None                   # raises CommandRejected(code)

# engine/testing.py
class FakeEngine: ...   # replays contract/fixtures, so A2 can build the API before the real engine
```

Tag `engine-api-v1`. A2 is then unblocked.

## Done when

- [ ] Boot fails on bad IDs, missing `asserts_on`, missing rationale
- [ ] Tag `engine-api-v1` exists and `FakeEngine` replays the fixtures

# A-01 · Skeleton and store (A2 half)

**Agent A2 · hours 2–4 · worktree `tc-a2`** · depends on `contract-v1`

**Read only:** architecture §10.1, §15

## Goal

The repository layout of architecture §15, a store whose integrity the database enforces, and the GPU lock.

## You may create or edit

- `pyproject.toml`
- `Makefile`
- `.importlinter`
- `tests/conftest.py`
- `store/sqlite.py`
- `tests/store/**`
- `scripts/with-gpu`

## Steps (tests first)

1. `pyproject.toml` (Python 3.12: fastapi, uvicorn, pydantic v2, pyyaml, pytest, ruff, import-linter). `Makefile` targets `dev-api` (inside tmux, see WORKFLOW §2.4), `test`, `gate`. `.importlinter`: `engine` must not import `api`, `store`, or `recommenders`.
2. **Tests first, `tests/store/`:** the behaviors in §10.1: a live session with a scenario is rejected; an orphan event is rejected; `UPDATE` on events is rejected; deleting events of an open session is rejected; purge works events-first and fails session-first.
3. `store/sqlite.py`: the §10.1 SQL verbatim, a connection factory that sets `PRAGMA foreign_keys = ON` on every connection, and `purge(retention_days)` in one transaction, events first.
4. `scripts/with-gpu`: the GPU lock (docs/ROSTER.md §5.3). Model-dependent jobs run through it:

```bash
#!/usr/bin/env bash
exec flock /tmp/tc-gpu.lock "$@"
```

## Done when

- [ ] `scripts/gate.sh a` passes
- [ ] Store tests pass
- [ ] `make dev-api` exists (a placeholder app is fine)
- [ ] `scripts/with-gpu` exists
- [ ] No file outside your directories changed
